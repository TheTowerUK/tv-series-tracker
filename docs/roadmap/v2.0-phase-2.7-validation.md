## Security and privacy audit

- No Admin API, service-role key, database password, personal access token, JWT signing secret, user/session token, or TMDB token was introduced into the browser, repository, Pages artifact, report, or test fixture.
- Passwordless authentication used the ordinary controlled-user browser path. Public signup remains disabled and the user count remains one.
- Ordinary browser writes continue to use only the five ordinary mutation RPCs. Migration remains isolated to `tracker_migrate_v1`; `tracker_restore_v2` has no browser UI invocation.
- The Edge Function has no tracker database access, service-role dependency, query-history storage, or analytics.
- Direct authenticated table DML and receipt DELETE remain unavailable.
- No staging/production project, second user, restore UI, offline queue, Realtime/BroadcastChannel, middle-season renumbering, or deferred synchronization feature was introduced.
