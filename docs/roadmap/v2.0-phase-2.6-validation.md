## Authority and recovery model

Local authority and writable cloud authority are deliberately separate. Local mutations continue through the LocalStorage repository. Cloud mutations pass through the sync controller and the five ordinary RPCs; the controller then rereads the complete owner-scoped tracker and only exposes that verified result as authoritative.

A conflict preserves the submitted context but does not retry it. Fresh cloud data is presented for review, and any retry is a new user-approved operation using the refreshed decimal-string revision. An uncertain write or failed reread enters `cloud_stale_readonly`; recovery performs only fresh reads. The last verified cloud snapshot remains visible and LocalStorage is never substituted as current cloud state.

## Deferred boundaries

- Restore-v2 browser UI remains deferred; `tracker_restore_v2` has no application caller.
- Offline queues, mutation replay, automatic deferred synchronization, Realtime, and `BroadcastChannel` coordination remain deferred.
- Middle-season renumbering and aggregate show-plus-season mutation RPCs remain out of scope.
- Phase 2.7 owns the TMDB Edge Function, hosted linking/deployment, and its separately approved security configuration.
- Production/staging deployment and release work remain separately gated.
